# Kishuto 聚合源 —— 手机/电视自动更新（已部署完成）

## 一句话用法

**在手机或电视的 TVBox / 影视仓里，「配置地址」（或「添加仓库」）填这一行：**

```
https://gitee.com/tao060702/tvbox/raw/master/tvbox.json
```

不用往手机里拷任何文件。配置里第一个站点 `Kishuto 聚合` 的 `api` 指向云端的
`tv/<版本号>/Kishuto.py`，壳会自己下载并缓存执行。

之后电脑上更新完（见「日常更新」），手机**重启一次壳**就是新版：

- 配置里 `api` 的路径里带版本号（`tv/20261105200237/`），版本一变地址就变
- 壳是按 api 字符串给 py 做缓存的，地址变了必然重新下载
- 就算壳没重下，py 里的门面启动时还会比对清单、自己覆盖自己

> 为什么不用 `?v=` 查询参数：不少壳是靠 `api.endswith(".py")` 判断「这是 python 源」的，
> 挂上参数就判不出来了，会当成未知类型。所以版本号放**路径**里。

## Kishuto 是什么

桌面一个 `Kishuto.py`（约 310 KB），把六个源合成一条：

| 顶层源 | 标记 | 说明 |
|---|---|---|
| **咕噜** | `gg` | **首页 / 分类 / 筛选的主源**（T3 私有协议，6 大类 + 类型/地区/排序筛选） |
| 影探 | `yt` | 影探 4K CMS，内含影探4K / 咕噜 / 橘汁4K / 找剧 四路线路 |
| 稀饭 | `xf` | 稀饭动漫，内含稀饭 / GiriGiri / 次元城 / OmoFun 四路 |
| 小鸡 | `xj` | 小鸡看看（五头签名 + 设备号池） |
| FoFo | `ff` | FoFo 影院（HTML + 凯撒解密） |
| 小山 | `sz` | 小山影视（登录 + ticket 换流） |

行为：

- **首页 = 影探**（最新电影/热播国剧/新外语片/欧美剧/韩剧/短剧/国漫/国综/少儿动画/热门电影①②③，最多 12 个分类）+ 影探推荐 30 条
- 豆瓣片单（移植自摸鱼 jar 里的 PianDan）代码仍在，`HOME_SOURCE='pd'` 可切回：综合热榜 / 热门电影 / 电影片库 / 热播剧集 / 剧集片库 / 综艺片库 / 动漫片库 / 电影榜单 / 剧集榜单 / 综艺榜单 十类，数据走 `m.douban.com/rexxar` 接口；**动漫片库用稀饭的推荐**。点开卡片才去六个源聚合搜片名找线路
- **分类** = 走 `gg|分类id`，带咕噜的筛选条件
- **搜索** = 六源并发合并，结果 `vod_remarks` 前带 `[源名]` 标记（约 2 秒）
- **详情** = 主源详情 + 其余五源按标题模糊匹配（`best_match` 0.62 阈值）拉线路，
  同名同集数的重复线路自动去重，通常 25~50 条线路
- **播放** = 选题里的线路 id 里编了源 tag，回原源取直链；失败时各源自己的降级逻辑照常生效

## 网盘扫码登录（2026-11-06）

电视壳不能弹对话框，所以二维码放**详情页海报位**：

1. 打开「Kishuto 诊断」站点 → 分类「网盘账号」
2. 点「📲 扫码登录 夸克网盘」或「📲 扫码登录 百度网盘」
3. 海报位出现二维码，用对应 App 扫，手机上确认
4. **返回再点一次同一张卡** → 显示「登录成功」，cookie 自动落盘

链路：

| 网盘 | 取码 | 轮询 | 换 cookie |
|---|---|---|---|
| 百度 | `passport.baidu.com/v2/api/getqrcode`（官方 PNG） | `/channel/unicast?channel_id=sign` | `/v3/login/main/qrbdusslogin?v=…` |
| 夸克 | `uop.quark.cn/cas/ajax/getTokenForQrcodeLogin` → 二维码指向 `su.quark.cn/4_eMHBJ?token=…`（图片走 `api.qrserver.com`） | `/cas/ajax/getServiceTicketByQrcodeToken` | `/cas/login?ticket=…` |

- 落盘文件 `.kish_auth.json`，依次尝试 `~`、`%TEMP%`、py 同目录
- 读取优先级：站点 `ext` 里的 cookie **高于** 落盘文件
- 玩偶源启动时自动读这个文件，所以扫完一次，之后不用再管

### 玩偶怎么播

站点是 MacCMS，详情页只有网盘分享（夸克/百度）。夸克配 cookie 才出直链：

```json
ext: {"qk_cookie":"__pus=...; __puus=...", "bd_cookie":"BDUSS=...; STOKEN=..."}
```

- `__pus` / `__puus`：浏览器登录 pan.quark.cn → F12 → Application → Cookies
- 没配 cookie：`parse=1` 把分享页交给壳的 webview（能看到页面，不一定直接出画面）
- 配了 cookie：`playerContent` 走 `/file/download` 拿直链，带 `Referer: https://pan.quark.cn/`
- 百度当前只做分享页跳转；直链要「转存 → filemetas」，接口已留位

## 搜索去重（2026-11-06）

- 六个源并发搜，**影探回来 + 另外 2 个源到齐**就收工（上限 2.8s），实测平均 0.88s；同词 10 分钟内再搜 0.000s。
- **同一部片只出一张卡**：`_base_name()` 会剥掉语种/中配/手语/解说/特别篇/番剧等 60+ 个后缀、括号注释、`-` 后的副标题、结尾年份与「第N季」；卡片备注显示 `[影探·3源]` 表示几个源都有。
- 不相关的结果直接过滤（搜「凡人修仙传」不会再出现「时间规划局」）。
- 想调噪音词：改 `Spider.NAME_NOISE` / `NAME_CUT`。

## 踩过的坑（都已内置处理）

| 坑 | 现象 | 处理 |
|---|---|---|
| **Gitee CDN 缓存** | 刚 push，raw 还是旧内容，设备判"已最新"不更新 | URL 加时间戳 query 破缓存 + 每轮重拉清单 |
| **清单与脚本不同步** | 清单落后一版 → sha 永远对不上 | sha 不符时按脚本内 `CODE_VERSION` 兜底，最多重试 3 轮 |
| **中文文件名** | urllib 遇非 ASCII 路径直接 `UnicodeEncodeError` | 云端统一 ASCII 名；发布工具再做百分号编码 |
| **合并同名符号** | 咕噜那段也有 AES/P-256 原语，直接拼会覆盖影探那套 | 合并时按顶层命名冲突表整体改名（`g_` 前缀） |
| **`http.client` 别名** | `import http.client as X` 后写 `X.client.X` 必崩 | 合并后统一改成 `X.HTTPSConnection` |
| **`lives: []`** | TBox 报「配置解析失败」，日志 `echo-load-config_live` 后紧跟 `IndexOutOfBoundsException: Index 0 out of bounds for length 0` | 壳解析配置时会取 `lives[0]`，空数组直接越界。配置里固定带一条空直播（指向 `live.m3u`） |
| **站点太多拖慢启动** | 壳启动会把配置里每个 site 的 py 都预热一遍，5 个文件串行 5.2 秒 | `tvbox.json` 只留 Kishuto 一个站点 |
| **仓库休眠** | Gitee 对长期不登录账号会暂停仓库，raw 变 404 | **每 2~3 个月登录一次 Gitee** |
| **令牌泄露** | 令牌存在 `public/.git/config` 的 remote URL 里 | 别把 `public/` 整个打包发人 |

**传播延迟**：Gitee 边缘缓存通常 1~3 分钟，`deploy.py` 会自动等到生效再报完成。

## 发布产物两处坑（发布必看）

1. **`assets/pack/` 必须随 py 一起推**。这个目录里的文件是某个版本 py 的配套
   数据，只推 py 不推它，设备拉下来会在装载阶段直接抛错、整个源不可用。
   `publish.py` 末尾会打印本次该目录下的文件名，推之前对一眼。
2. **`assets/pack/` 只增不删**。按版本号命名，设备上残留的旧版 py 还要配它用；
   自动清理只动 `tv/` 下的旧版本目录，不要手工删这个目录。
3. **保护层里的 `class Spider` 签名占位不能删**。壳在装载前会先扫文本里的类名
   和方法名，扫不到就直接判「下载到的不是 python 源」（加密第一版就是这么被拒的）；
   真正实现由载荷在文件末尾覆盖它。`guard.py` 的自检会核对这几行还在。
