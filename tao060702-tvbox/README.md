# TVBox 多源订阅配置

一个用于手机 / 电视 TVBox、影视仓类客户端的 **Python 源订阅仓库**。
仓库本身只存放配置文件与自建的采集脚本，不存储、不分发任何影视资源。

---

## 订阅地址

在客户端的「配置地址 / 添加仓库 / 订阅管理」里填这一行即可，无需往设备里拷任何文件：

```
https://gitee.com/tao060702/tvbox/raw/master/tvbox.json
```

影视仓的「多源仓库」入口也可以填同一个地址（对应 `repo.json`）。

## 徽章包地址（建议用这个）

在客户端的「徽章 / 标签 / 角标」设置里填：

```
https://gitee.com/tao060702/tvbox/raw/master/badge_pack_tbox.json
```

> **之前用的是别人分享的徽章包、图标加载不出来（空白、裂图、只剩文字）的，换成本仓库这一个。**
>
> 包里 493 条标注规则、对应的 493 张图标全部由本仓库 `badges/` 目录直接提供，
> 配置和图标的版本一一对应，不依赖任何第三方图床；国内可直连，不会因为外链失效而整片空白。
> 若填完首发仍是旧图标，重启一次客户端（Gitee 有短暂缓存）。

## 自动更新是怎么工作的

- 每个站点的 `api` 指向 `tv/<版本号>/<源>.py`，**版本号写在路径里**。
  版本一变，地址就变，客户端按地址缓存 py，因此必然重新下载。
- 不用 `?v=` 查询参数，是因为不少客户端靠 `api.endswith(".py")` 判断源类型，
  带参数会被判成未知类型。
- 根目录的 `update_<源>.json` 是各源的版本清单（含 `version` / `url` /
  `sha256` / `size` / `note`），`version.txt` 是当前版本号。
- 发布后 Gitee CDN 有短暂缓存，设备**重启一次客户端**即可拉到新版；
  若首次仍是旧版，再重启一次即可。

## 目录结构

```
tvbox.json              订阅主配置（站点 / 播放标识 / 直播源）
repo.json               影视仓「多源仓库」入口
version.txt             当前版本号
update_*.json           各源的版本清单
live.m3u                默认直播源
Kishuto.py              多源聚合源（最新副本）
xifan.py                稀饭聚合源（最新副本）
tv/<版本号>/            定版副本（只保留最近 3 个，路径变化触发客户端重下）
badges/                 线路徽章图标
badge_pack_tbox.json    徽章配置
badge_pack_full.zip     徽章图标打包
CHANGELOG.md            版本变更记录
NOTICE.md               使用条款与免责声明
.gitee/                 Issue 反馈模板
```

## 常见问题

- **刚发布没更新**：等 CDN 传播，然后重启客户端；不要在地址后面加 `?t=` 之类参数。
- **某条线路放不出来**：线路可用性取决于上游站点，同片通常还有其它源可换；
  详情页里的线路已按可用性排过序，靠前的更稳。
- **徽章图标空白 / 裂图 / 只显示文字**：用的是第三方徽章包、外链图标挂了。换成上面
  「徽章包地址」里本仓库那个（`badge_pack_tbox.json`）即可，图标与配置同仓库同版本。
- **换一集就慢一次**：源内已做直链缓存、后台预热与线路并发竞速，首次取流仍取决于上游接口响应速度。
